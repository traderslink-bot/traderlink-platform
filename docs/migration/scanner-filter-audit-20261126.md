# Scanner filter and combination audit

November 26, 2026. The initial audit of the private editor at `/scanner` used source `2364d714d`. This audit covers all entries in its picker, the 52 entries and subchoices in the older Moomoo editor, and the filter families in the master plan. The six original live presets have their own server logic. Results, chart overlays and evidence readouts count as filters here only when a trader can select a corresponding rule.

The seven-runner engine replay covers all six presets, the exact rolling price/volume fix, ordered PR and halt reactions, same-time RVOL and 4,000-symbol timing. [Results and remaining coverage limits](scanner-engine-runner-replay-20261127.md)

For the two ordered reactions, the trader chooses the permitted elapsed minutes. The press release must be visible to that reader and strictly earlier than the completed reclaim. The result keeps the article that qualified even when a newer release exists. The resumption rule requires the full candle to begin at or after **trade** resumption and close within the window with volume at least twice its preceding baseline. A quote resumption alone supplies no qualifying trade event.

Study timeframes run from 1m through weekly where the inputs support the calculation. SPY comparisons require aligned daily or weekly observations. Weighted studies require intraday bars carrying actual VWAP. Long lookbacks and thinly traded names can have insufficient observations. Higher-timeframe requests read existing split-adjusted archive coverage; the evaluator does not schedule a backfill. None of these filters requires a new paid provider.

The browser regression runs the actual editor, evaluator, saved-book routes and persistence in isolation. It checks each new rule has a qualifying result across the controlled nano-cap rows, the submitted and saved definitions agree, and the results and settings survive a page reload, reopen and reapply. The event tests cover a later unrelated release, reverse order, equal timestamps, expired windows, weak volume and a bar straddling resumption. A second saved scan combined the two ordered reactions under All; only the ticker with both qualifying events returned, with the original PR attached after reopening. The broader 12-file run passed 140 tests. The final focused five-file run passed 35, including the 400-bar shared-history regression and both browser round trips. Source coverage has not been measured across the live universe for this batch. ### Private roster export implemented in the Scanner candidate

Scanner owns `GET /api/internal/company/v1/roster`. It uses a dedicated read-only bearer configured by `TRADERLINK_COMPANY_ROSTER_READ_TOKEN`. The successful private, uncached JSON response contains `sourceDate` (accepted roster trading date), `acceptedAtUtc`, sorted `tickers: string[]` and `calendar: { from, through, tradingDates, digest, evidenceDigest }`. The dates span the verified exchange-calendar snapshot containing today's Eastern date. `digest` is lowercase hex SHA-256 of the UTF-8 bytes of JavaScript `JSON.stringify({ from, through, tradingDates })` in that key order. `evidenceDigest` identifies the underlying calendar evidence. Missing credentials, unreadable/absent membership and unverified calendar coverage cannot publish an empty replacement roster.

The VPS consumer owns its durable local revision. An identical poll is idempotent. Accept a calendar-only change with the same roster acceptance timestamp. On conflicting membership with the same source date and timestamp, retain the last accepted membership and flag the conflict. Preserve the real roster date on holidays. Release owns any hosted configuration and publication.

## Where AND, OR and IF belong

- **Current rule language.** Choose All (AND) or Any (OR) for the scan and independently for each group. Root rules and groups are siblings. Each group accepts rules only. A blank scan is unfiltered. A partially entered numeric rule or empty group blocks Apply. Numeric bounds include equality. Lists match any selected value inside the rule. One scan accepts up to 128 rules in total.
- **Multiple conditions at the same observation.** Price up 30% AND float at most 10M AND (recent PR OR resumed trading) is directly expressible. A known winning OR branch qualifies the ticker even when the other branch lacks data. In an AND, one known failure rules it out. Otherwise unresolved inputs keep the ticker in the incomplete count. The explicit include-unknown-float setting changes only that float predicate. Per-rule coverage under All counts the rows actually reached before a failure.
- **Conditional thresholds today.** To require 500K traded in premarket or 1M during regular hours, use outer Any and two All groups. Each group includes its own session and volume basis. After hours neither group qualifies. Missing required volume stays unknown in the active branch. Add a third explicit after-hours group only if the trader wants an after-hours rule. Saving is optional.
- **News-dependent thresholds today.** For a 10M float cap with a recent PR and a 5M cap without one, use outer Any and two All groups, each with the same PR window and its own float cap. Available news with no qualifying PR makes the second branch eligible. Unavailable news remains unknown.
- **Repeated ranges.** For price below one band OR inside another band, put the two Price rules in an Any group. The top-level picker reopens an existing common rule when added twice; the group picker permits independent copies. There is no general NOT, strict/inclusive switch, test for whether a field is available, or group inside a group. For some expressions this means repeating common conditions. A named-list exclusion or use-a-fallback-only-when-float-is-unknown rule needs a corresponding predicate.
- **Optional future IF control.** An IF/ELSE form might make long session or cap-band branches easier to read. Give it exact boundaries and an explicit outcome when the condition is unknown. One possible rule would use a fallback volume/liquidity test only when float is unavailable. Today, including unknown float also accepts unknown float without demanding that fallback.
- **Events in order.** “After a PR, the ticker crosses VWAP within five minutes” is different from “both occurred in the last five minutes.” A cross before the PR satisfies the latter. Add event ordering, ticker identity, event timestamps and a permitted elapsed interval for a true follow-through filter. A generic IF button would not implement this. The same applies to resume followed by volume expansion, and breakdown followed by recovery. Existing named structure signals handle their own defined sequences only.
- **Original PR finding (fixed in the local candidate).** The editor reconstructs saved PR windows of one hour or more as hours rounded to three decimals. For 61 minutes, the stored window is 3,660 seconds. Rebuilding the editable draft gives 1.017 hours, or 3,661.2 seconds. Selecting the saved scan initially uses its original definition. Apply or Save changes can alter the cutoff with no threshold edit. The same rounding when switching units turns one minute into 0.001 days (86.4 seconds). Preserve the entered duration through reopen and unit switches.
