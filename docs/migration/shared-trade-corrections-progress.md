# Permanent trade corrections for Shared Charts

The Gateway is the sole writer. Its independent SQLite file defaults to `~/.config/traderlink/alpaca-trade-corrections.sqlite` and can be set with the existing Gateway configuration's absolute `tradeCorrectionLedgerPath`. The ledger uses schema version 1, private file mode, WAL and full synchronous commits. A provider correction notice is durably queued by ticker and Eastern session before REST reconciliation. Pending notices resume on restart. Publishing a complete confirmed repair commits minute replacements or removals and settles the corresponding notice in one transaction. Candle retention cannot prune this ledger.

The ledger appends confirmed revision rows. Repeated notices for unchanged candle facts retain the same generation, and later revisions supersede earlier minutes. Compatible legacy archive corrections are imported without writing to the read-only archive. The exact three reviewed POM revisions, including their witnessed stale OHLCV and trade VWAP inputs, initialize the ledger idempotently.

## Consumer contract

- `/trade-revisions` uses a half-open UTC millisecond window. It accepts up to 400 unique tickers and 730 days, with a 65,536 affected-minute limit per request. It returns an optional durable generation and per-symbol revision digest, pending flag and sorted UTC-second minute starts.
- `/trade-correction-evidence` uses a half-open UTC millisecond window for one ticker, with a 3,660-day and 4,096-row limit. It returns ordered raw SIP revisions, witnessed stale candles, replacements or explicit removals, and the durable generation. Optional `daily=1` reads as many as four completed native day witnesses from the ledger. Chart history can explicitly opt into `dailyReplay=1` for a cold witness. Broad consumers make cache-only reads. Both server requests have neutral wire forms. The limits fail explicitly rather than truncating confirmed minute rows.
- Ordinary SIP history applies raw corrections directly on the verified source basis. Older split-adjusted reads require covered split events and an unchanged symbol lineage within the applied events. A minute-derived aggregate needs complete compatible minute coverage. Native Daily uses a separate complete SIP trade replay and exact native OHLCV comparison.
- Read-only archive aggregation projects within the archive's verified price-basis fingerprint and snapshot. Unverified coverage results in a miss. Accepted inputs affected by a new committed correction are withdrawn from current use. The verified history path can reissue a receipt when it can recompose the exact corrected series on the original qualified symbol, split and session basis.
- Moomoo's cache retains raw native candles. The projection uses exact witnessed native OHLCV or a previously equivalent repaired candle at the same timestamp. It applies Moomoo split factors after the raw comparison. Native interval and Daily comparisons require their own coverage and witnesses. Different provider-native observations remain separate.
- An open Moomoo chart can receive a recent-window revision notice and request fresh native history. The notice carries no SIP replacement prices. Provider-native quote-only highs and affected feature caches need their own qualified input or consumer fence.

## Release and recovery

Keep the archive read-only. Release must preserve an existing ledger or take a coherent SQLite backup before changing an existing ledger deployment. Use the SQLite backup API or copy a closed checkpointed database. File-only copies from an active WAL are insufficient. If this is the first installation, record that the new ledger path was absent and preserve the previous binary for runtime rollback. Roll back only the Gateway and App artifacts if needed. Retain the ledger and newer confirmed revisions for the next restart. Restoring an older backup over newer ledger rows requires a reconciliation and is a separate operation.

Isolated tests cover persistence across Gateway reopen, a notice saved before confirmation across Eastern midnight, a 65th ticker above the active batch cap, duplicate notices, later revisions, a qualifying Daily witness, same-basis Alpaca history, read-only archive aggregation, and qualifying versus incompatible Moomoo candles. The Chromium replay used recorded POM candles and mocked provider HTTP and stream transport. Open and fresh POM views agreed on the corrected $7.41 premarket high and 30,566,502 shares. A 1m direct correction and a 15m qualified-history reload both matched their fresh chart VWAP series.

The browser replay is implementation evidence. The production ledger path, live-provider comparable Moomoo candles and the signed-in combined consumer rollout still need Release integration and verification.
