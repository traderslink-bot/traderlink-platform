# TraderLink Stock Screeners — Alpaca implementation plan

**Table-first design approved · November 14, 2026 · `/screeners`**

Companion: [progress and build gates](stock-screeners-alpaca-progress.md).

## First release decision

The table-first Screeners page opens on **All covered U.S. stocks**. The whole covered stock universe is evaluated by default. My tickers selects a subset of that universe. Market cap starts at Any and accepts a minimum, maximum, range or quick pick. Shortcuts include Under $5M, $20M, $50M, $100M, $200M, $500M, $1B and $10B. A cap filter requires a known cap. Existing screens saved under the former $200M default retain an explicit Under $200M rule.

A read-only VPS test covered 5,845 listings and found regular-session prices for 5,839. Preparing a cold snapshot took 171.3 seconds at the paced request budget. A prepared snapshot ran 100 queries with a median of 5.8 ms and a 95th percentile of 10.4 ms for filtering, sorting and selecting the first page. The app shares prepared data and makes zero Alpaca requests when a user clicks Run. Scheduled refresh, storage and provider headroom determine operational capacity. See the progress record for the test conditions and market-hours follow-up.

The isolated owner preview uses a prepared Alpaca SIP snapshot. The provider collector writes an atomic market snapshot for an approved private transfer to the Platform data directory. The collector uses bounded concurrent REST reads, caches daily history and reuses session bars with an overlapping update window. The current source includes collector and reader code. Market-hours staging verifies supply and freshness before member display. Historical replay, CSV, saved-screen alerts and personal watchlist writes remain follow-on work.

## 1. Product decision

Build a stock discovery workspace that answers “Which stocks match my rules right now?” Start from a TraderLink preset or a blank screen, choose a universe and session, run, inspect the matches, and save the screen to use again. Support both the TraderLink small-cap workflow and a broader U.S. stock universe. Give breadth through an organized filter catalog, with a short default toolbar and a small set of visible columns.

- **Screeners (`/screeners`)** provides user-controlled, timestamped results. A run shows one market snapshot, and results stay stable while the user reads, sorts, or opens a chart. Sorting and paging use the pinned results while they remain in the server cache. The cache holds up to six runs per account and 64 per server process and evicts the oldest runs when it fills. `Run screen` applies rule changes. `Refresh results` reruns the applied screen against the latest available snapshot, including when a run has been evicted. No automatic reranking at launch.
- **Scanners (`/scanners`):** continuous, event-driven detection. Preserve existing cards, alert logic, market-cap limits, subscriptions, and delivery behavior. `/scanner` remains the separately guarded legacy Moomoo tool; reuse useful product ideas, not Moomoo field IDs or assumptions. Leave existing `/api/screeners/live` and chart contracts intact.
- The assigned checkout already has a distinct `/screeners` placeholder using `DashboardPage` and `hasWatchlistDashboardNavigationAccess`, and a separate `/scanners` route. Keep the current access check on the page and enforce it independently on every API; add a feature flag for controlled rollout. Member access must also satisfy data display rights. Remove “Coming soon” for eligible users when their feature is enabled.

**Build order:** prove the source and coverage → launch useful Alpaca screens and saved workflows → deepen setup and catalyst filters → add independently sourced company/ownership data. Stock research only; no orders, locates, public sharing, or recurring user alerts in the initial feature.

## 3. Universe and time model

1. **All covered U.S. stocks.** Match active Alpaca U.S. equity records to the Nasdaq Trader listed and other-listed directories by symbol and exchange. Use the test and ETF flags and security name descriptors to exclude identifiable test issues, funds, notes, warrants, rights, units and preferreds. The covered population can include common shares, ADRs and REITs. Expose incomplete venue or classification coverage. My tickers filters within this population. Qualifications for ETFs, OTC and additional data products are separate. Market cap comes from the Nasdaq, NYSE and NYSE American listing data and can remain unavailable for otherwise eligible names. [Nasdaq Trader directory definitions](https://www.nasdaqtrader.com/Trader.aspx?id=SymbolDirDefs) · [Alpaca Assets](https://docs.alpaca.markets/us/reference/get-v2-assets-1)
2. **Session:** `Premarket`, `Regular`, `After hours`, `Last completed regular`. Start with the current supported session on a new unsaved screen; use Last completed regular on weekends/closures unless an entitled extended session is actually open. Explain inactive sessions or no data yet. Label date and time in ET and keep overnight as its own mode. Settlement/late/trade-report prints are subject to eligibility rules; a regular session ends at the exchange calendar's actual close. Use Eastern market dates and UTC storage; never infer a trading day from the VPS clock or a fixed offset.
3. **Intervals:** Session for live price/volume; daily for swing/longer horizons; add 1m, 5m, 15m, 1h and weekly (monthly only when justified) for technical filters after warming and coverage tests. Each filter and corresponding result column displays its interval. Regular-only technical windows by default; future extended-hours technicals have separate series. Live price can compare with a completed indicator; a crossover uses two completed comparable bars. Intraday windows cannot cross incompatible session/feed boundaries without an explicitly named rule.
4. **A run binds an immutable snapshot:** universe version, data watermark, session/date, feed, adjustment basis and metric versions. A separate refresh creates a new snapshot. Show `Matches / evaluated`, total in scope and how many couldn't be evaluated, with reason counts. Track separate source clocks and time bounds. one recent event or fetch timestamp doesn't make all fields current. No daily values overwritten by after-hours data. Delayed SIP, IEX, last complete snapshot and unavailable feed are distinct states; show only approved alternatives and make switching explicit. A ranking of SIP and IEX values mixed together would be meaningless.

### Calculation rules to lock before coding

| Metric | Definition / failure behavior |
| --- | --- |
| **Change vs prior close** | `100 × (eligible price / prior regular close on current split basis − 1)`. Open gap instead uses the first qualified regular-open value. Before the open show `Premarket change vs prior close`, not a regular gap. After-hours change uses the same trade date's regular close. A missing qualified anchor means unavailable. Chart evidence must align with the same session and adjustment when comparing. |
| **RVOL at time** | `Shares through completed bucket / mean shares through the same elapsed bucket of the previous 10 or 20 eligible sessions`. Same feed, session, phase offset and comparable split basis; exclude current session from baseline; verify the expected buckets, early closes, coverage and sample minimum (proposed at least 8 of 10 or 16 of 20); denominator must be positive. A known no-trade bucket can be zero, an unknown or missing page cannot. The distinct `Volume vs 20-day average` uses full-session historical denominators and has a separate label. [TradingView](https://www.tradingview.com/support/solutions/43000635874-how-do-we-calculate-relative-volume-and-relative-volume-at-time/) also separates prior-period RVOL from same-clock comparisons; its screener's per-bar definition differs from the proposed cumulative metric. |
| **Dollar volume and VWAP** | Exact trade notional only when the existing eligible-trade aggregation reports complete coverage. Otherwise use `Σ(bar VWAP × bar volume)` only if the documented bar inputs qualify, visibly mark **estimated**, and preserve source/method in exports and tooltips; never substitute last price × volume. Session VWAP uses matching session inputs and a consistent eligibility policy; if not exact, label the bar-based method. Reconcile with chart definitions before surfacing a same-named metric. |
| **Spread** | `Ask − bid`; bps `10,000 × (ask − bid) / midpoint`. Require coherent positive bid and ask, an age limit and indicated feed; crossed/missing/stale quotes are unavailable. A valid locked quote may be zero and should be identified. Do not show a stale spread as current or assume IEX is the NBBO. |
| **Returns and levels** | Trading-session counts by named methodology (e.g. 5/21/63/126/252 market sessions for 1w/1m/3m/6m/1y, YTD anchors to prior year last regular close). Separate split-adjusted price return from any later dividend-adjusted total return. Daily indicators use completed regular sessions and documented seeds/warm-up; exclude forming bars unless explicitly marked. Use same adjusted basis across history, today's raw eligible trade and prior close; avoid double adjustment and remember old historical prices were expressed on their then-current basis. Show incomplete 52-week history as unavailable or label a separate `Since listing` range. Compare prior extremes excluding the bar being tested. |
| **Filter truth** | Compare unrounded normalized values; display up to four decimals and four for sub-$1 prices. Freshness/availability is per source and metric. Unknown never passes a numeric/negative filter through zero-fill or `NOT`; explicit `Is unavailable` can select it. In grouped logic an OR branch can pass independently; unknown counts are rows that cannot be resolved after evaluating the full tree. Nulls sort last both ways. Fundamentals and corporate events carry fiscal/date basis and last updated/reported time; refuse incompatible periods, share classes or restatements. |

## 5. Interface and user workflow

**Approved layout.** Use a table-first screen with a visible filter bar and an expandable rule editor. TradingView's [screen library, filter finder, column sets and table/chart views](https://www.tradingview.com/support/solutions/43000718866-tradingview-stock-screener-trade-smarter-not-harder/), Finviz's [organized filters and saved presets](https://finviz.com/knowledge-base/screener/getting-started-with-screener/introduction-to-screener), and Stock Analysis's [exact criteria and ranked-entry workflow](https://stockanalysis.com/tutorials/screener/) inform the pattern. Keep TraderLink's square panels, shared light Material shell, real dropdowns/buttons, compact orange tickers, green/red direction, and existing chart/news behavior where it fits. No generic text under the page title.

1. **Open and run.** Screeners opens with editable custom filters for All covered U.S. stocks, or with the user's saved default when set. The `Screen` dropdown opens TraderLink presets and My screens. `New screen` clears the current screen and starts with custom filters. The filter bar stays visible and contains `Add filter`, `Market cap`, the multi-select `Exchanges` picker, `OR group` and `Run screen`. A stock must pass every standalone rule and one rule in each OR group. Each rule can exclude its matches. Use `Sort` and the optional `Then by` to order results. Browse metric groups or type a field into `Add filter`, then set its value in the rule editor. Tap a rule chip to reopen it. `Save screen` asks for a name when the user chooses to save a new screen. Every run uses a prepared snapshot. Display the timestamp, feed and result coverage above the table, and show `Unapplied changes` until the next successful run.
2. **Build rules.** Edit each rule in a compact panel beneath the filter bar on desktop and phones. The catalog groups fields by category and supports typing to search. Add an inline row with interval, operator and compact value input. Support ≥, >, ≤, <, equality and ranges. Place market-cap shortcuts and editable bounds in one compact control. Later add one-of, above/below field and crosses/recently-within. Accept and normalize `250k`/`1.5M` and `2x` with clear units. Basic combines filters with AND; advanced adds bounded groups under explicit `Match all`/`Match any`. Each group is visible and understandable; no raw formulas or unbounded nested trees. Chips show session/interval when relevant. Removing a rule or undoing a single change is easy. Draft rule edits remain while you inspect rows. `Cancel` restores applied rules; `Reset` restores chosen preset/default after an explicit user action. Client offers syntax feedback; server owns validation.
3. **Read and inspect.** Default columns: Ticker (company secondary), Price, Session change, Volume, relative activity if enabled, Spread or ATR by preset, row actions. Offer `Summary`, `Liquidity`, `Technicals`, `Catalysts` (when enabled) and custom column sets. Multi-sort with stable ticker/asset tie break; column chooser to show/reorder/reset. When a filter uses a hidden field, surface it in the match detail and let the user add it as a column. Show the matching values, thresholds, timestamps and any applicable data gaps in `Why it matched`. Display manageable pages (default 50, max 100); preserve order and scroll while inspecting. Chart, news/PR and watchlist actions sit beside the relevant ticker, with chart using the shared component and plus using a verified **user-owned** watchlist target (never publishing to the owner Watchlist). If no appropriate write contract exists, launch with chart/news only and add plus when qualified.
4. **Views and mobile.** Table is the default. Keep Table, Cards and Two rows as common view choices and keep the same core data/actions across views. Build Table + compact Two rows first; deliver Cards and the same accessible ticker actions during the first UI acceptance batch before calling the initial feature complete. Cards show a few compact reads and optionally a short cached price chart later; one detailed chart uses the existing shared chart/news drawer path. Ticker stays sticky in a horizontal table; put a verified country flag beneath it in Two rows; reserve absent PR action space. Use compact scrollable results, optional in-card details, generous tap separation, and portrait/landscape controls that keep rows in view. Desktop chart/details may open beside results if space permits; mobile can overlay with clear close, restored scroll and keyboard focus. Avoid a permanent full-height filters rail by default.
5. **Save and reuse.** Platform-user-owned private screens: add, rename, duplicate, update, delete with confirmation, set default, and preserve settings (filters, universe, session, sort, view, columns). Save As protects the original preset. Version definitions and show when an imported/older rule is unavailable. Last-used state may restore independently of named screens; failed saves preserve the draft. Saving a configuration does not save a vendor data file. CSV export (if permitted) uses selected safe columns, timestamps, session, feed, methodology and snapshot coverage; limit rows and neutralize spreadsheet formulas. Bulk add checked tickers to a personal list only after owner/permissions and UX review. Later: share **rule templates**, not vendor result data or private watchlist members; opt-in alerts for names entering a saved screen only after dedupe/cooldown, freshness and rights gates. Keep alert actions separate from running a screen.
6. **Feedback states.** Show one concise status if warming, `Market closed · Last regular session …`, explicit delayed/stale timestamp, partial results with source missing counts, rate-limited retry, no matches with removable rules, and recoverable errors while retaining the last successful snapshot. A real empty result is distinguishable from an unavailable feed. Example: `38 matches · 5,870 evaluated of 6,021 · 151 missing required data · Regular · Alpaca SIP · 10:35 a.m. ET` (illustrative only). Accessible names on icon buttons, keyboard tab/arrow behavior, Escape close, live announcements for a completed run, status text in addition to color, and focus/scroll restoration. Help gets a new Screeners entry, a first-run recipe and metric/freshness definitions; keep the Scanners Help destination.

### Sharing inside TraderLink

Users save their own screens privately under My screens. Share sits beside Duplicate on a saved screen. The dialog can create a member link and separately opt the saved version into Community presets. A recipient opens the preset on Screeners, sees its rules, and can run it against the market data they can access. Save a copy creates an independent, editable screen under their account. Shared fields include the saved title, filters, exchanges, session, sort and columns. A screen scoped to a personal ticker list is private.

The share link identifies a fixed version. Saving edits that keep the screen on All covered U.S. stocks leaves that version intact. Saving with My tickers revokes the link and removes its gallery listing. Switching back to All covered U.S. stocks makes the screen eligible for a new link. Authors can remove a gallery listing separately or turn off sharing entirely. Deleting the private source also removes access to the shared version. Previously saved copies remain usable. The Community presets picker lists only member-published versions and shows their author. A recipient can report a preset through the existing support contact.

Use the existing Screeners feature access for link reads, gallery browsing and publication. Serve only configuration through sharing. Keep member saves and run results under the current account scope. Store the share catalog in the Screeners persistent directory and include it in the staging backup and restore test. Verify separate owner and recipient behavior, stale publication attempts, revocation, the link and gallery from the phone preview, and saving a copy after opening a published screen.

## 6. Backend and scale plan

**Relative volume and recent press releases.** Add both to the existing filter picker, sortable columns and saved screens. Relative volume compares SIP share volume through the last completed 15-minute window with the same elapsed time in the prior ten sessions. Require eight comparable dates, with the same session start and enough session length to reach the chosen cutoff. The collector pages split-adjusted history separately and reuses it on warm refreshes. Add an Unusual Volume preset with a volume floor. Recent Press Releases uses the time since publication in the existing member-visible TraderLink feed, with a custom window of up to 48 hours. Use a single indexed read for each screen run that needs the metric. Missing evidence remains unavailable. Offer both metrics in Why it matched and preserve the source scope and time on the run.

**Recent volume, gap fills and premarket-high breaks.** Count shares in the last completed 5 or 15 minutes of the selected session, ending at the snapshot's bar cutoff. A fully collected window with no trades has zero volume when the stock has other observed activity in that session. Gap fill status compares the observed regular open with the previous regular close and checks whether a completed regular bar reached that close. Premarket high uses the same market date's completed premarket bars. A strict break above it during a completed regular bar stays marked even if the price pulls back. Both signals require a regular session and the relevant reference data. The collector uses the existing split-adjusted five-minute bars and fetches the premarket for the last completed regular session on warm and cold collection paths.

**Opening range and VWAP.** Expose the first 5, 15, 30 and 60 minutes of regular trading as selectable price positions, highs, lows and widths. Complete the window before publishing its levels and require a post-window price for a position. Treat the range endpoints as Inside range. Use completed five-minute SIP bars and their volume-weighted VWAPs to estimate VWAP separately for each session. The signed distance is relative to that VWAP.
